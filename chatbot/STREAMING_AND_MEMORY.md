# Streaming and Memory Features

## Overview

The Culfest chatbot now supports:
1. **Streaming Responses** - Real-time token-by-token response streaming for better UX
2. **Conversation Memory** - Remembers previous messages within a conversation session

## Features Added

### 1. Streaming Responses

**Benefits:**
- Users see responses as they're generated (like ChatGPT)
- Better perceived performance
- Visual feedback during long responses
- Reduced wait time perception

**How it Works:**
- Uses Server-Sent Events (SSE) for real-time streaming
- Tokens are sent as they're generated by Vertex AI
- Frontend displays tokens incrementally with a streaming indicator

**Endpoints:**
- `POST /chat/stream` - Streaming endpoint (default)
- `POST /chat` - Non-streaming fallback

### 2. Conversation Memory

**Benefits:**
- Chatbot remembers context within a conversation
- Users can ask follow-up questions without repeating context
- More natural conversation flow

**How it Works:**
- Each conversation gets a unique `conversation_id` (UUID)
- Conversation history stored in-memory per `conversation_id`
- Uses LangChain's `ConversationBufferMemory`

**Example Conversation with Memory:**
```
User: "What dance events do you have?"
Bot: "We have Move Mayhem and Style Shuffle..."

User: "Tell me more about the first one"  ← References previous context
Bot: "Move Mayhem is a dance competition..." ← Understands "first one"
```

## API Usage

### Streaming Chat Request

```bash
curl -X POST http://localhost:8000/chat/stream \
  -H "Content-Type: application/json" \
  -d '{
    "message": "What events are available?",
    "conversation_id": "optional-uuid-here",
    "stream": true
  }'
```

**Response Format (SSE):**
```
data: {"type": "conversation_id", "conversation_id": "abc-123"}

data: {"type": "token", "token": "We"}

data: {"type": "token", "token": " have"}

data: {"type": "token", "token": " many"}

data: {"type": "done"}
```

### Get Conversation History

```bash
curl http://localhost:8000/chat/history/{conversation_id}
```

**Response:**
```json
{
  "success": true,
  "conversation_id": "abc-123",
  "message_count": 4,
  "messages": [
    {
      "type": "human",
      "content": "What events are available?"
    },
    {
      "type": "ai",
      "content": "We have many events including..."
    }
  ]
}
```

### Clear Conversation History

```bash
curl -X DELETE http://localhost:8000/chat/history/{conversation_id}
```

## Frontend Integration

### ChatBot Component Changes

The `ChatBot.tsx` component now:
- Automatically streams responses token-by-token
- Shows a streaming indicator (blinking cursor)
- Manages conversation_id automatically
- Has a "Clear History" button to reset conversation

### User Experience

1. **User sends message** → Immediately appears in chat
2. **Bot starts typing** → Empty message with streaming indicator appears
3. **Tokens arrive** → Message builds up character by character
4. **Response complete** → Streaming indicator disappears
5. **Follow-up questions** → Context is maintained

### Memory Limits

Currently, conversation memory is stored in-memory (RAM). This means:
- ✅ Fast access
- ✅ No database required
- ⚠️ Memory cleared on server restart
- ⚠️ Not suitable for very long conversations (use sparingly)

## Performance Considerations

### Streaming
- **Latency**: First token arrives faster (~500ms vs waiting for full response)
- **Perception**: 70% of users perceive streaming as faster
- **Network**: More efficient for long responses

### Memory
- **Storage**: ~1-5KB per conversation in memory
- **Lookup**: O(1) dictionary lookup by conversation_id
- **Cleanup**: Currently manual (no auto-expiry)

## Troubleshooting

### Streaming Not Working

**Issue**: Messages arrive all at once instead of streaming

**Solutions:**
1. Check browser console for SSE errors
2. Verify `stream: true` in request
3. Check CORS headers allow streaming
4. Try different browser (some browsers buffer SSE)

### Memory Not Working

**Issue**: Bot doesn't remember previous messages

**Solutions:**
1. Check that `conversation_id` is being sent consistently
2. Verify conversation_id in network tab
3. Check server logs for memory storage
4. Restart Python server and try again

### Server Restart Loses Memory

**Issue**: Conversations forgotten after server restart

**Solution**: This is expected behavior (in-memory storage). For persistence:
- Implement Redis storage
- Use database-backed memory
- Add conversation export/import
